Privacy

What Id|le keeps, what it sends, and how to turn each thing off. This page describes what the game's code actually does; if the code changes, this page changes with it.

In short: your worlds, your drawer and any AI keys stay in your browser. The site counts a few anonymous things (no cookies, nothing about you or your world), and it can read public web pages for your creatures. Both can be switched off in ⚙ settings.

Kept in your browser, not sent

  • Your worlds: the creatures, words, pictures, buildings, snapshots, the almanac's history and the family trees are stored in this browser (its local storage and IndexedDB). Clearing the site's data in your browser removes them, so save a backup file now and then (the snapshot menu does that).
  • Your drawer: the things you keep are stored in this browser too.
  • The chat and your AI keys: if you connect an AI in the chat, your key is stored in this browser and is sent only to the provider you chose (for example api.anthropic.com, or the address you typed for an OpenAI-compatible or local model). It never goes to id-le.com, and it is never put in a world file or a snapshot. What you type in the chat goes to that provider too, under their terms, and nowhere else.

To see how new players get on, the public site sends a few counts from each visit. On by default; turn it off in ⚙ settings → Anonymous stats, and nothing more is sent from that browser.

Not sent: anything from your world (names, words, pictures, buildings), your chats, AI keys, your address, or an identifier that follows you between visits. Id|le sets no cookies.

Where it goes: to id-le.com itself, which only adds the counts to daily totals (for example "41 visits, 30 on phones"). Single visits are not stored, and neither are addresses. The totals are kept for about a year. Stats are only counted on the public site: never on a copy you run yourself.

The public helper (reading web pages)

Some creatures read real web pages (Crawlers, and travel mode). A web page isn't allowed to fetch other sites by itself, so id-le.com does it for you: it fetches the public page you or your creatures asked for and hands it back to your browser.

  • Only public http/https addresses; private and local network addresses are refused.
  • It identifies itself to the site as the Id|le helper. Page sizes are capped and each visitor is limited to 60 requests a minute (that count lives in memory for a minute and is never stored).
  • What is fetched is not logged. The hosting network may briefly cache a fetched public page (up to about ten minutes) to be quicker the second time.
  • Linking worlds (optional, in 🌐 connect): to link two worlds, the helper keeps what linking needs, which is your world's code and the name you give it, the links you approve, the creatures and souvenirs on their way between linked worlds, and when each world was last open.

Turn it off in ⚙ settings → Public helper: no pages are read for that browser and linking pauses; the features that need it say so.

The data lab (Jeffy classifiers)

In the 🧪 data lab, creatures are real text classifiers from Jeffy, a sister project by the same author. To label a message, the helper sends that message's text (at most 500 characters) and the classifier's name to Jeffy's public server, playground.jeffyclassify.com, and returns the label.

  • Only the text being classified is sent, in batches from many visitors at once, through the endpoint that does not keep the text. Nothing else about you or your world is sent.
  • Requests are limited (20 a minute per visitor, and a cap on how many are in flight) so the shared server stays responsive; when it is busy, creatures simply wait.
  • The request comes from id-le.com's helper, not from your browser, so Jeffy's server does not see your network address; it logs that a batch arrived, as most web servers do.

The data lab only runs when you open it. Turning off the public helper in ⚙ settings also turns this off.

Hosting

id-le.com is a static site served by Cloudflare. Like any website, the hosting network handles your connection to deliver the pages; Id|le has not turned on any request logging of its own.
